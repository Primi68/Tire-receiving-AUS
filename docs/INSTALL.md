# Tire Receiving 설치 및 데이터 이전

대상 버전: **0.1.2**

릴리스 태그: **`v0.1.2-mvp`**

APK: **`Tire-Receiving-0.1.2-preview.apk`**

## 지원 환경

- Android 8.0(API 26) 이상
- Package: `com.primi.tirereceiving`
- Version: `0.1.2` / `versionCode 3`
- 인터넷 연결 없이 APK의 계산·기록·백업 기능 사용 가능

## GitHub Release에서 설치

저장소가 비공개이므로 접근 권한이 있는 GitHub 계정이 필요합니다.

1. <https://github.com/Primi68/Tire-receiving-AUS/releases>를 엽니다.
2. `v0.1.2-mvp` 릴리스를 선택합니다.
3. 다음 세 파일을 같은 위치에 받습니다.
   - `Tire-Receiving-0.1.2-preview.apk`
   - `SHA256SUMS.txt`
   - `SIGNING-CERT-SHA256.txt`
4. 아래 방법으로 APK 체크섬과 서명 인증서를 확인합니다.
5. Android 기기에서 APK를 열고, 요청될 때 해당 브라우저 또는 파일 앱의 **알 수 없는 앱 설치**를 허용합니다.
6. 설치가 끝나면 임시로 허용한 설치 권한을 다시 끕니다.
7. Tire Receiving을 열어 초기 타이어가 14개인지 확인합니다.

공식 `v0.1.2-mvp` Release가 아닌 workflow artifact나 출처를 확인할 수 없는 APK를 현장 기기에 설치하지 않습니다.

## 파일 무결성 확인

macOS 또는 Linux:

```bash
sha256sum -c SHA256SUMS.txt
```

macOS에서 `sha256sum`이 없다면:

```bash
shasum -a 256 Tire-Receiving-0.1.2-preview.apk
```

출력값을 `SHA256SUMS.txt`의 값과 비교합니다.

Android SDK Build Tools가 설치된 컴퓨터에서는 서명 인증서를 확인할 수 있습니다.

```bash
apksigner verify --verbose --print-certs Tire-Receiving-0.1.2-preview.apk
```

`Signer #1 certificate SHA-256 digest`가 `SIGNING-CERT-SHA256.txt`의 지문과 같아야 합니다. 체크섬 또는 인증서 지문이 다르면 설치하지 말고 릴리스 파일을 다시 받습니다.

## 첫 실행 확인

설치 직후 실제 현장 기록을 입력하기 전에 다음을 확인합니다.

1. 홈 화면에 **오프라인 앱** 상태가 표시되는지 확인합니다.
2. Tire presets에서 초기 타이어 14종을 확인합니다.
3. 검수 시작 → E80 HK Front 20" → Orange를 선택합니다.
4. `20 × 4 × 9 + 36 = 756`과 예상 756, 차이 0이 표시되는지 확인합니다.
5. 테스트 기록 한 건을 저장하고 Records에서 열어 수정·삭제가 되는지 확인합니다.
6. 테스트 백업을 내보낸 뒤 파일이 생성되는지 확인합니다.

실제 기종별 검증 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록합니다.

## 업데이트 설치

같은 package와 같은 고정 서명 키로 만든 더 높은 `versionCode` APK는 기존 앱 위에 설치할 수 있습니다. 정상적인 덮어쓰기는 로컬 데이터를 유지하지만, 업데이트 전에 항상 JSON 백업을 만듭니다.

1. 기존 앱에서 **데이터 관리 → 백업 내보내기**를 누릅니다.
2. 저장된 JSON 파일이 열리는지 확인하고 승인된 위치에 복사합니다.
3. 새 Release의 APK 체크섬과 서명을 확인합니다.
4. 새 APK를 열어 기존 앱 위에 설치합니다.
5. 타이어 마스터와 최근 기록이 남아 있는지 확인합니다.
6. 계산 한 건과 새 백업 내보내기를 확인합니다.

Android가 **앱이 설치되지 않았습니다** 또는 서명 충돌을 표시하면 기존 앱을 바로 삭제하지 마세요. 새 APK가 공식 릴리스의 고정 서명으로 만들어졌는지 먼저 확인합니다. 기존 앱을 삭제하면 앱 내부 로컬 데이터가 삭제됩니다.

## JSON 백업

백업에는 현재 타이어 마스터와 모든 검수 기록이 들어갑니다.

1. 앱 우측 상단의 데이터 메뉴를 엽니다.
2. **백업 내보내기**를 선택합니다.
3. Android 문서 선택기에서 승인된 폴더를 고르고 저장합니다.
4. 기본 파일명 `tire-receiving-backup-YYYY-MM-DD.json`을 유지하거나 날짜와 기기를 구분할 수 있게 이름을 정합니다.
5. 앱 외부의 승인된 저장 위치에 사본을 둡니다.

앱 삭제, 기기 교체, 기기 초기화, 앱 데이터 지우기 전에는 반드시 백업합니다. Android 시스템 자동 백업은 비활성화되어 있습니다.

## JSON 복원

복원은 현재 타이어 마스터와 검수 기록 **전체를** 백업 내용으로 교체합니다.

1. 현재 상태도 필요하면 먼저 별도 JSON으로 내보냅니다.
2. **데이터 관리 → 백업 복원**을 누릅니다.
3. Android 문서 선택기에서 Tire Receiving이 만든 JSON을 고릅니다.
4. 화면에 표시된 프리셋 수와 기록 수를 확인합니다.
5. 교체 확인을 누릅니다.
6. Tire presets와 Records에서 필요한 데이터가 들어왔는지 확인합니다.

앱은 JSON 구조, 랙 색상, 상태, 숫자 필드를 확인합니다. 형식이 잘못된 파일은 복원하지 않습니다. Android 앱은 최대 20MB의 JSON 파일을 처리합니다.

## 앱을 삭제하거나 기기를 바꿀 때

1. 기존 기기에서 JSON 백업을 내보냅니다.
2. 파일 크기가 0이 아닌지 확인합니다.
3. 새 기기에 공식 APK를 설치합니다.
4. 새 기기에서 JSON을 복원합니다.
5. 타이어 개수, 최근 기록, 마지막 기록의 수량을 기존 기기와 비교합니다.
6. 확인이 끝난 뒤에만 기존 앱과 임시 백업을 정리합니다.

앱 삭제 시 APK의 로컬 기록은 함께 삭제됩니다. 별도로 내보낸 JSON 파일은 사용자가 삭제할 때까지 선택한 위치에 남습니다.

## 웹 버전

웹 앱은 <https://tire-receiving-floor-check.coral-peony-2632.chatgpt.site>에서 사용할 수 있습니다.

- 첫 접속과 새 버전 수신에는 네트워크가 필요합니다.
- 지원 브라우저에서는 앱 셸이 캐시된 뒤 오프라인으로 열릴 수 있습니다.
- 데이터는 해당 브라우저와 사이트의 Local Storage에 저장됩니다.

- APK 데이터와 자동으로 동기화되지 않습니다. 두 환경 사이 이동에는 JSON 백업·복원을 사용합니다.

## 문제 해결

### APK가 설치되지 않음

- Android 8.0 이상인지 확인합니다.
- 다운로드가 완전한지 `SHA256SUMS.txt`로 확인합니다.
- 같은 package의 다른 서명 앱이 설치되어 있는지 확인합니다.
- 기존 데이터를 백업하기 전에는 앱을 삭제하지 않습니다.

### 실행 후 빈 화면

- 앱을 완전히 닫았다 다시 엽니다.
- Android System WebView와 Chrome을 기기에서 지원되는 최신 버전으로 업데이트합니다.
- 문제가 반복되면 Android 버전과 기종을 검증 기록에 남깁니다.

### 기록이 사라짐

- APK와 웹 앱 중 어느 환경에서 기록했는지 확인합니다.
- 다른 브라우저 프로필이나 시크릿 모드를 사용했는지 확인합니다.
- 최근 JSON 백업을 복원합니다.

### 백업 파일을 열지 못함

- 확장자가 `.json`인지 확인합니다.
- 20MB 이하인지 확인합니다.
- 편집기로 일부만 잘라 저장한 파일이 아닌지 확인합니다.
- 현재 데이터를 먼저 내보낸 뒤 원본 백업을 다시 선택합니다.
